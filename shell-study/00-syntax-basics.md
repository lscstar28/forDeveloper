# 쉘 문법 기초 — 줄바꿈/공백/괄호가 어떻게 작동하는가

[02-shell-scripting.md](02-shell-scripting.md)를 보기 전에, 쉘이 텍스트를 어떤 "단위"로 나눠서 읽는지부터 알아야 한다.
쉘은 사람이 읽는 것처럼 "문장"을 이해하는 게 아니라, 정해진 규칙대로 문자열을 **토큰(단어)** 단위로 잘라서 처리한다.

---

## 1. 줄바꿈(개행) = 명령어의 끝

쉘의 기본 명령어 구분자는 **개행(`\n`)**이다. 한 줄 = 보통 하나의 명령어.

```bash
echo "A"
echo "B"
```

한 줄에 여러 명령어를 넣고 싶으면 `;`로 구분한다. 즉 `;`는 "여기서 줄이 끝난 것처럼 취급해라"는 뜻.

```bash
echo "A"; echo "B"          # 위 두 줄과 완전히 동일하게 동작
```

### 명령어를 연결하는 연산자

```bash
cmd1 ; cmd2       # 그냥 순서대로 실행 (cmd1 성공/실패 상관없이 cmd2 실행)
cmd1 && cmd2      # cmd1이 성공(exit 0)해야만 cmd2 실행
cmd1 || cmd2      # cmd1이 실패해야만 cmd2 실행
cmd1 &            # cmd1을 백그라운드로 실행하고 바로 다음 줄로
cmd1 | cmd2       # cmd1의 출력을 cmd2의 입력으로 (파이프)
```

### 한 줄을 여러 줄로 "이어쓰기"

줄 끝에 `\`(백슬래시)를 붙이면, 쉘은 다음 줄이 이어서 오는 걸로 취급한다 (개행을 무시).

```bash
echo "이것은" \
     "한 줄로 " \
     "취급된다"
```

파이프(`|`)나 `&&`, `||`, 여는 괄호 뒤에서 줄이 끝나면, 쉘은 "아직 명령어가 안 끝났다"는 걸 자동으로 알아채고 다음 줄을 이어 받는다 (`\` 없이도 가능).

```bash
cat file.txt |
    grep "error" |
    wc -l
```

> 터미널에서 이렇게 입력 중이면 프롬프트가 `>`로 바뀌는데, "아직 명령어가 안 끝났다"는 쉘의 표시다.

## 2. 공백(스페이스) = 단어(word)를 나누는 구분자

쉘은 명령줄을 읽을 때 **공백/탭 기준으로 "단어(word)" 리스트**로 쪼갠다. 이걸 **word splitting**이라 한다.

```bash
echo hello world foo
```

이 줄은 쉘 입장에서 `["echo", "hello", "world", "foo"]` 라는 4개의 단어로 보인다. **첫 단어 = 실행할 명령어, 나머지 = 그 명령어에 넘길 인자들.**

중요한 규칙: 연속된 공백/탭은 몇 개든 상관없이 구분자 하나로 취급된다.

```bash
echo hello        world     # "hello"와 "world" 사이 공백이 몇 개든 결과는 같음
```

### 변수를 인용부호 없이 쓰면 위험한 이유

변수 확장(`$var`)의 결과도 그 안에 공백이 있으면 다시 word splitting이 일어난다.

```bash
file="my report.txt"
touch $file          # 위험: touch가 인자를 "my"와 "report.txt" 두 개로 받는다 → 파일 2개 생성 시도
touch "$file"        # 안전: 인자 1개("my report.txt")로 전달됨
```

**변수는 항상 `"$var"`처럼 따옴표로 감싸는 게 기본값**이라고 생각하면 된다. (배열 전체를 펼칠 때의 `"$@"`도 같은 원리)

## 3. 인용부호(quoting) 3종

| 문법 | 안에서 변수(`$x`) 확장됨? | 안에서 공백이 단어를 나눔? | 특징 |
|---|---|---|---|
| `'...'` (single quote) | ❌ 아니오 | ❌ 아니오 | 안의 내용을 100% 글자 그대로 |
| `"..."` (double quote) | ✅ 예 | ❌ 아니오 | 변수/명령치환은 되지만 공백에 안 쪼개짐 |
| `\x` (backslash) | - | - | 바로 다음 글자 딱 하나만 특별한 의미를 없앰 |

```bash
name="World"
echo 'Hello $name'     # 출력: Hello $name   (그대로 문자로 취급)
echo "Hello $name"     # 출력: Hello World   (변수 확장됨)
echo Hello\ $name      # 출력: Hello World   (공백을 \ 로 escape해서 단어 안 나뉨)
```

## 4. 괄호류 총정리 — 생긴 게 비슷해도 역할이 다 다르다

| 문법 | 이름 | 용도 | 새 프로세스(subshell)? |
|---|---|---|---|
| `( 명령어 )` | 서브쉘 | 명령어들을 그룹으로 실행, 안에서 변수 바꿔도 바깥엔 영향 없음 | 예 |
| `{ 명령어; }` | 그룹 명령 | 그룹 실행이지만 지금 쉘 그대로 사용 (변수 공유됨) | 아니오 |
| `$( 명령어 )` | 명령어 치환 | 명령어의 출력 결과를 문자열 값으로 사용 | 예 |
| `` `명령어` `` | 명령어 치환(구식) | `$( )`와 동일, 중첩이 불편해서 요즘은 안 씀 | 예 |
| `(( 식 ))` | 산술 평가 | 정수 계산/비교. 조건문으로도 사용 가능 | 아니오 |
| `$(( 식 ))` | 산술 치환 | 계산 결과를 값으로 꺼내옴 | 아니오 |
| `[ 식 ]` | test 명령 | 조건 검사 (POSIX 표준, `[`는 실제로 명령어 이름) | 아니오 |
| `[[ 식 ]]` | 조건식 | 조건 검사 (bash 확장, `&&`/`||`/패턴매칭 가능) | 아니오 |
| `${ 변수 }` | 파라미터 확장 | 변수값 꺼내기 + 문자열 자르기/치환 등 | - |
| `{a,b,c}` | 중괄호 확장 | 나열된 문자열을 각각 펼침 | - |
| `{1..5}` | 중괄호 확장(범위) | 숫자/문자 범위를 순서대로 펼침 | - |

### `( )` 서브쉘 vs `{ }` 그룹 — 가장 헷갈리는 차이

```bash
x=1
( x=2 )              # 서브쉘 안에서 바꿈 → 서브쉘이 끝나면 바깥엔 영향 없음
echo "$x"            # 1  (안 바뀜)

x=1
{ x=2; }             # 그룹 명령은 지금 쉘 안에서 그대로 실행됨
echo "$x"            # 2  (바뀜)
```

`{ }` 문법 주의사항: `{`는 사실 예약어라서 **뒤에 공백이 꼭 있어야 하고**, 안의 마지막 명령어 뒤에 **`;` 또는 개행이 꼭 있어야** 닫는 `}`가 인식된다.

```bash
{ echo hi; }     # OK
{echo hi;}       # 에러: { 뒤에 공백 없음
{ echo hi }      # 에러: 마지막 명령 뒤에 ; 나 개행 없음
```

### `[ ]` vs `[[ ]]`

`[ ]`는 사실 `test`라는 이름의 명령어다 (즉 `[`가 프로그램 이름). 그래서 안의 각 요소는 전부 "인자"로 취급되고, 인자 사이에 공백이 필수다.

```bash
[ "$a" = "$b" ]      # [ 와 ] 양쪽에 공백 필수 (실제로 [는 명령어라서)
[[ $a == $b ]]       # bash 확장 문법. 변수에 따옴표 안 붙여도 비교적 안전, && || 직접 사용 가능
```

## 5. 쉘이 한 줄을 처리하는 실제 순서

쉘은 아래 순서로 한 줄을 해석한다 (bash 기준, 축약):

1. **토큰화**: 공백/구분자 기준으로 단어들로 자른다
2. **확장(expansion)** — 아래 순서대로 진행:
   - 중괄호 확장 (`{a,b,c}`, `{1..5}`)
   - 물결 확장 (`~` → 홈 디렉토리)
   - 변수/명령치환/산술치환 (`$var`, `$(...)`, `$((...))`)
   - word splitting (공백 기준으로 다시 쪼개기 — 인용부호로 막을 수 있음)
   - 경로명 확장 / glob (`*.txt` → 실제 파일 목록으로 펼침)
3. **인용부호 제거**: 확장이 다 끝난 뒤 `'`, `"`, `\` 문자 자체는 제거됨
4. 남은 단어들을 **명령어 + 인자**로 실행

이 순서를 알아야 아래 같은 게 왜 그렇게 동작하는지 이해된다:

```bash
touch "*.txt"     # 따옴표 안이라 glob 확장이 안 일어남 → 실제로 "*.txt"라는 이름의 파일 생성됨
touch *.txt       # 따옴표 없음 → 쉘이 현재 폴더에서 .txt 파일 목록으로 미리 펼쳐서 넘김
```

### glob(경로명 확장)이 정확히 뭔가

**glob**은 `*`, `?`, `[...]` 같은 와일드카드 패턴으로 **파일/폴더 이름을 매칭**시키는 방식이다. 정식 이름은 "경로명 확장(pathname expansion)"이고, "glob"은 옛날 유닉스의 같은 이름 보조 프로그램에서 유래한 별칭이다.

가장 중요한 개념: **명령어(`ls`, `touch`, `rm` 등)는 `*`가 뭔지 전혀 모른다.** `*`를 실제 파일 목록으로 바꾸는 건 명령어가 아니라 **쉘**이고, 그것도 명령어를 실행하기 전, 2번 단계(확장)에서 이미 끝나 있는 일이다.

```bash
ls *.txt
# 쉘이 먼저 현재 폴더를 뒤져서 *.txt 에 매칭되는 실제 파일들을 찾고
# ls a.txt b.txt c.txt   <- ls는 이 상태(이미 펼쳐진 목록)만 받아서 실행한다
```

자주 쓰는 glob 패턴:

| 패턴 | 의미 | 예시 |
|---|---|---|
| `*` | 아무 문자나 0개 이상 (길이 상관없음) | `*.txt` → 모든 .txt 파일 |
| `?` | 아무 문자나 정확히 1개 | `file?.txt` → file1.txt, fileA.txt (o) / file10.txt (x) |
| `[abc]` | 대괄호 안의 문자 중 하나 | `file[123].txt` → file1.txt, file2.txt, file3.txt |
| `[a-z]` | 범위 지정 | `[a-z]*.txt` → 소문자로 시작하는 .txt 파일 |
| `[!abc]` | 대괄호 안의 문자를 **제외**한 하나 | `file[!0-9].txt` → 숫자가 아닌 한 글자 |

매칭되는 파일이 하나도 없으면 (기본 설정에서는) 패턴 문자열 그대로가 인자로 전달된다 — 즉 `echo *.zzz`인데 .zzz 파일이 없으면 `*.zzz`라는 글자 그대로 출력됨. 그래서 "펼쳐졌다"와 "안 펼쳐졌다"를 헷갈리기 쉬우니 주의.

> 정규표현식(regex, `grep -E`나 `sed` 등에서 쓰는 것)과 문법이 비슷해 보이지만 **완전히 다른 규칙**이다. 예를 들어 glob의 `*`는 "바로 앞 문자의 반복"이 아니라 "아무 문자열이나"라는 뜻으로, regex의 `.*`에 더 가깝다. 이 둘을 섞어 쓰면 헷갈리기 쉬우니 별개로 기억하자.

## 6. `exit` — 쉘/스크립트를 즉시 종료시키는 명령어

`exit`는 내장 명령어(builtin)로, 지금 실행 중인 쉘(또는 스크립트)을 그 자리에서 즉시 끝내고 **종료코드(exit status, 0~255)**를 반환한다.

```bash
exit 0        # 성공했다는 뜻으로 종료 (관례: 0 = 성공)
exit 1        # 실패했다는 뜻으로 종료 (관례: 0이 아닌 값 = 실패, 보통 1)
exit          # 숫자를 안 주면 '바로 직전에 실행된 명령의 종료코드'를 그대로 반환
```

이 종료코드는 스크립트를 실행시킨 쪽(다른 스크립트, CI 파이프라인, 사람이 친 다음 명령 등)이 `$?`로 읽어서 성공/실패를 판단하는 데 쓰인다.

```bash
./script.sh
echo $?       # script.sh가 exit 몇으로 끝났는지 확인
```

스크립트 안에서 `exit`가 특히 자주 쓰이는 패턴은 `||`(02번 문서에서 다룬 조건부 실행)와 결합해서 "실패하면 더 진행하지 말고 여기서 끝내라"는 가드로 쓰는 것이다.

```bash
cd /some/dir || exit 1
```

읽는 법: `cd`가 실패하면(`||`이므로 앞이 실패했을 때만 뒤가 실행됨) 그 즉시 `exit 1`로 스크립트 전체를 종료. `cd`가 성공하면 `|| exit 1` 부분은 아예 실행되지 않고 다음 줄로 넘어간다.

> 주의: 터미널에 직접 `exit`를 치면 그 터미널 세션(대화형 쉘) 자체가 닫힌다. 스크립트 파일 안에 있는 `exit`는 그 스크립트 프로세스 하나만 끝낸다.

## 7. `--` — "여기부터는 옵션이 아니라 그냥 값이다" 표시

대부분의 명령어(POSIX 관례를 따르는 프로그램들)는 인자 목록 중간에 `--`가 나오면 **"이 뒤에 오는 건 전부 옵션(`-`로 시작하는 플래그)으로 해석하지 말고 그냥 일반 인자로 취급해라"**로 받아들인다.

왜 필요한가: 파일 이름이 하필 `-`로 시작하면, 명령어가 그걸 옵션 플래그로 착각해버릴 수 있다.

```bash
touch -- -weird-file.txt     # "-weird-file.txt"라는 이름의 파일을 만든다
rm -weird-file.txt            # -- 없이 이렇게 쓰면 rm이 "-weird-file.txt"를 파일명이 아니라
                               # 알 수 없는 옵션으로 착각해서 에러를 낸다
rm -- -weird-file.txt         # --로 선을 그어주면 뒤의 것은 무조건 파일명으로 처리됨 → 정상 삭제
```

`examples/00-syntax-basics.sh`에 나오는 `rm -f -- *`도 같은 이유다. `*`는 현재 폴더의 파일 목록으로 펼쳐지는 glob인데(위 5번 문단 참고), 만약 그 목록 안에 `-i`나 `-rf`처럼 옵션처럼 생긴 이름의 파일이 우연히 있으면 `rm`이 그걸 옵션으로 잘못 해석할 위험이 있다. `--`를 붙여두면 "`*`로 펼쳐진 것들은 전부 옵션이 아니라 파일명"이라고 명시적으로 못박는 셈이라, 실무에서 흔히 쓰는 안전한 관용구다.

```bash
rm -f -- *      # 현재 폴더의 모든 파일 삭제. 이름이 -로 시작하는 파일이 섞여 있어도 안전
```
