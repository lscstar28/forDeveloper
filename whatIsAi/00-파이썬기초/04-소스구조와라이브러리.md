# 소스 구조 파악하기 — 어디까지가 내가 쓴 코드인가

코드를 읽을 때 가장 먼저 나눠야 할 4가지 구분:

| 구분 | 설명 | import 필요 여부 | 예시 |
|---|---|---|---|
| 🔵 **파이썬 내장(built-in)** | 파이썬 자체가 기본으로 제공. 언제나 바로 쓸 수 있음 | 필요 없음 | `print`, `len`, `range`, `open`, `int` |
| 🟢 **표준 라이브러리** | 파이썬 설치 시 같이 깔려있지만, 쓰려면 `import`로 불러와야 함 | `import` 필요 | `os`, `sys`, `urllib` |
| 🟣 **외부 라이브러리(서드파티)** | 우리가 `pip install`로 따로 설치한 남이 만든 코드 | `import` 필요 | `torch`, `torch.nn` |
| 🟠 **우리가 직접 작성** | `model.py`, `train.py` 등 우리 파일 안에서 `def`/`class`로 정의한 것 | - | `class MiniGPT`, `def main` |

이제 우리 파일 4개를 위에서부터 끝까지 훑으면서 태그를 붙인다.

---

## 1. `download_data.py` — 가장 짧은 파일부터

```python
import os                          # 🟢 표준 라이브러리
import urllib.request               # 🟢 표준 라이브러리

URL = "..."                         # 🟠 우리가 만든 변수
DEST = os.path.join(...)            # os.path.join 🟢 라이브러리 함수 / DEST 🟠 우리 변수

if __name__ == "__main__":
    os.makedirs(...)                # 🟢 라이브러리 함수
    print(f"...")                   # 🔵 내장 함수
    urllib.request.urlretrieve(...)  # 🟢 라이브러리 함수
    size = os.path.getsize(DEST)     # 🟢 라이브러리 함수 / size 🟠 우리 변수
    print(f"...")                    # 🔵 내장 함수
```

**요약**: 이 파일은 실질적으로 우리가 만든 것이 거의 없다. `URL`, `DEST`, `size`라는 이름(변수)만 우리가 붙였고, **실제 일(파일 다운로드, 폴더 만들기, 파일 크기 확인)은 전부 `os`와 `urllib`이라는 라이브러리가 대신 해준다.** 우리는 그 라이브러리 함수들을 순서대로 호출만 한 것.

## 2. `model.py` — 여기부터가 "우리 코드"의 핵심

### 2-1. 맨 위 import (여기서 어떤 재료를 가져오는지 선언)

```python
import torch                          # 🟣 외부 라이브러리 (PyTorch 본체)
import torch.nn as nn                 # 🟣 외부 라이브러리 (신경망 레고 조각들이 모여있는 서브모듈)
from torch.nn import functional as F  # 🟣 외부 라이브러리 (수학 연산 함수 모음)
```

이 세 줄 이후로 나오는 `nn.으로 시작하는 모든 것`과 `F.로 시작하는 모든 것`, `torch.로 시작하는 모든 것`은 **우리가 만든 게 아니라 PyTorch가 이미 만들어놓은 것**이다. 우리는 이걸 "가져다 쓸 뿐"이다.

### 2-2. `nn.Module`을 상속하는 4개 클래스 — 여기가 "우리가 설계한 것"

```python
class Head(nn.Module):              # 🟠 클래스 이름/구조는 우리 것 (단, nn.Module 상속은 PyTorch 규칙)
    def __init__(self, n_embd, head_size, block_size, dropout):  # 🟠 우리가 정한 매개변수
        super().__init__()                          # 🟣 PyTorch 필수 초기화 (라이브러리 규칙)
        self.key = nn.Linear(n_embd, head_size, bias=False)   # nn.Linear 🟣 라이브러리 / self.key 🟠 우리가 붙인 이름
        self.query = nn.Linear(n_embd, head_size, bias=False)  # 🟣 + 🟠
        self.value = nn.Linear(n_embd, head_size, bias=False)  # 🟣 + 🟠
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))
        # register_buffer, torch.tril, torch.ones = 🟣 라이브러리 함수
        # "tril"이라는 이름표는 🟠 우리가 붙인 것
        self.dropout = nn.Dropout(dropout)          # 🟣 + 🟠

    def forward(self, x):            # 🟠 forward라는 이름은 PyTorch 규칙(반드시 이 이름), 내부 로직은 🟠 우리가 짠 것
        B, T, C = x.shape             # x.shape 🟣 라이브러리 속성 / B,T,C 🟠 우리가 붙인 변수명
        k = self.key(x)               # 🟠 self.key는 우리가 만든 속성이지만, 실제 연산은 🟣 nn.Linear 내부 코드가 수행
        q = self.query(x)
        wei = q @ k.transpose(-2, -1) * C ** -0.5
        # @ (행렬곱), .transpose = 🟣 라이브러리(PyTorch 텐서) 기능
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        # .masked_fill 🟣 라이브러리 / float() 🔵 파이썬 내장
        wei = F.softmax(wei, dim=-1)   # 🟣 라이브러리 함수
        wei = self.dropout(wei)         # 🟠 우리가 만든 속성 호출 (내부는 🟣)
        v = self.value(x)
        out = wei @ v
        return out                      # 🔵 파이썬 문법 (return은 내장 키워드)
```

**정리**: `Head` 클래스에서 **"이런 순서로 계산하겠다"는 설계(로직의 흐름)는 우리 것**이지만, `nn.Linear`, `torch.tril`, `F.softmax`, `@`(행렬곱), `.masked_fill` 같은 **실제 수치 연산은 전부 PyTorch가 대신 계산**해준다. 우리가 짠 건 "레고 조각(라이브러리 함수)을 어떤 순서로 조립할지"이고, 조각 자체(행렬곱, softmax 계산법)는 만들지 않았다.

같은 원리로 `MultiHeadAttention`, `FeedForward`, `Block`, `MiniGPT` 클래스도 전부 **"PyTorch 조각을 어떤 순서로 배치할지"를 정의한 것**이다. `MiniGPT`에서 쓰인 라이브러리 조각들만 모으면:

| 조각 | 하는 일 | 제공처 |
|---|---|---|
| `nn.Embedding` | 정수 → 벡터 변환표 | 🟣 PyTorch |
| `nn.Sequential` | 여러 층을 순서대로 연결 | 🟣 PyTorch |
| `nn.LayerNorm` | 값 정규화 | 🟣 PyTorch |
| `nn.Linear` | 가중치 곱하기 (선형변환) | 🟣 PyTorch |
| `F.cross_entropy` | 예측과 정답의 차이(loss) 계산 | 🟣 PyTorch |
| `F.softmax` | 확률분포로 변환 | 🟣 PyTorch |
| `torch.no_grad` | 학습 없이 계산만 하기 | 🟣 PyTorch |
| `torch.multinomial` | 확률에 따라 무작위 샘플링 | 🟣 PyTorch |
| `torch.cat` | 텐서 이어붙이기 | 🟣 PyTorch |

그리고 우리가 직접 만든 것(🟠)만 모으면:

| 이름 | 무엇인가 |
|---|---|
| `Head`, `MultiHeadAttention`, `FeedForward`, `Block`, `MiniGPT` | 클래스 5개 (설계) |
| `forward`, `generate` | 각 클래스 안에 정의한 메서드(동작 순서) |
| `n_embd`, `head_size`, `block_size`, `dropout`, `vocab_size`, `n_head`, `n_layer` | 우리가 정한 매개변수 이름 |
| `x`, `k`, `q`, `v`, `wei`, `out`, `idx`, `logits`, `loss` | 계산 중간중간 우리가 붙인 변수 이름 |

→ **결론: `model.py`에서 "새로 발명한 수학/연산"은 하나도 없다. 전부 PyTorch가 제공하는 조각들이고, 우리가 한 일은 "어텐션을 만들려면 이 조각들을 이런 순서·구조로 배치해야 한다"를 코드로 표현한 것.**

**정리 — `train.py`에서 우리가 만든 것 vs 라이브러리가 한 일**:

|---|---|
| 하이퍼파라미터 값 정하기 (`n_embd=128` 등) | 실제 텐서 연산, 자동미분(`backward`), 가중치 업데이트(`AdamW`) |
| 데이터 읽고 문자→숫자 변환 로직(`encode`/`decode`) 작성 | 텐서 생성/이동/저장 (`torch.tensor`, `.to()`, `torch.save`) |
| 학습 루프의 흐름(몇 번 돌지, 언제 로그 찍을지) 설계 | loss 계산 방식(`cross_entropy`, `model.py`에 있지만 PyTorch 함수), 확률적 샘플링 |
| 모델 구조 설계 (`model.py`) | 모델 구조를 이루는 개별 레이어(`nn.Linear` 등)의 실제 계산 |

## 5. 전체 그림 — 5개 카테고리로 다시 정리

| 기호 | 카테고리 | 이 프로젝트에서의 예시 |
|---|---|---|
| 🔵 | 파이썬 내장 함수 | `print`, `len`, `open`, `range`, `enumerate`, `sorted`, `int`, `list`, `set` |
| 🟢 | 표준 라이브러리 (`import` 필요, 파이썬에 기본 포함) | `os`, `sys`, `urllib.request` |
| 🟣 | 외부 라이브러리 (`pip install`로 설치, `import` 필요) | `torch`, `torch.nn`(`nn`), `torch.nn.functional`(`F`) |
| 🟡 | 우리가 만든 다른 파일에서 가져온 것 | `from model import MiniGPT` |
| 🟠 | 지금 이 파일 안에서 직접 정의한 것 | `class Head`, `def main`, `n_embd`, `wei`, `loss` |

**비유로 정리하면**: PyTorch(🟣)는 "레고 조각 세트"이고, 우리가 만든 `model.py`(🟠, 🟡)는 "이 조각들로 만든 조립 설명서"다. `train.py`는 그 조립품(모델)을 가져다 "실제로 데이터를 넣고 돌리는 작업 순서"를 짠 것. 우리가 잘한 일은 새 레고 조각을 발명한 게 아니라, **어떤 조각을 어떤 순서로 조립해야 "언어를 이해하는 것처럼 보이는 결과"가 나오는지 설계**한 것이다.

## 6. 자주 나오는 파이썬 내장(🔵) 함수 — 별도로 익혀두기

우리 코드 전체에서 반복적으로 등장하는 내장 함수들만 따로 모았다. 모두 `import` 없이 바로 쓸 수 있다.

| 함수 | 하는 일 | 예시 | 결과 |
|---|---|---|---|
| `print(x)` | 화면에 출력 | `print("hi")` | `hi` |
| `len(x)` | 개수(길이) 반환 | `len([1,2,3])` | `3` |
| `range(n)` | 0부터 n-1까지 숫자를 순서대로 생성 | `list(range(3))` | `[0, 1, 2]` |
| `int(x)` / `float(x)` / `str(x)` | 형(type) 변환 | `int("5")` | `5` |
| `open(경로, 모드)` | 파일 열기 | `open("a.txt", "r")` | 파일 객체 |
| `sorted(x)` | 정렬된 새 리스트 반환 | `sorted([3,1,2])` | `[1, 2, 3]` |
| `list(x)` / `set(x)` | 리스트/집합(중복제거)으로 변환 | `set("aab")` | `{'a', 'b'}` (집합은 순서 보장 안 됨) |
| `enumerate(x)` | (인덱스, 값) 쌍을 같이 꺼내기 | `list(enumerate(["a","b"]))` | `[(0,'a'), (1,'b')]` |
| `sum(x)` | 합계 | `sum([1,2,3])` | `6` |
| `min(x)` / `max(x)` | 최소/최대값 | `max([3,1,2])` | `3` |
| `abs(x)` | 절댓값 | `abs(-5)` | `5` |
| `type(x)` | 타입 확인 | `type(5)` | `<class 'int'>` |
| `zip(a, b)` | 두 리스트를 나란히 짝지어 순회 | `list(zip([1,2],["a","b"]))` | `[(1,'a'), (2,'b')]` |
| `input(x)` | 사용자 입력 받기 (터미널에서 타이핑 대기) | `input("이름: ")` | 입력한 문자열 |

이 표에 있는 함수들은 앞으로 어떤 파이썬 코드를 봐도 계속 마주치게 된다. 눈에 익혀두면 "이건 라이브러리가 아니라 파이썬이 원래 제공하는 기능이구나"를 바로 구분할 수 있다.

## 7. 실전 팁 — 낯선 코드를 볼 때 구분하는 방법

1. **파일 맨 위 `import` 목록을 먼저 본다** → 이 파일이 어떤 외부 재료(🟢🟣)를 쓰는지 한눈에 파악
2. **`이름.점(.)` 형태**를 보면: `.` 앞이 `import`한 모듈 이름이면 🟢/🟣, `self`나 우리가 만든 객체면 🟠일 가능성이 높음 (단, `self.xxx()`도 내부적으로 라이브러리 코드를 부를 수 있으니 정의부를 확인해야 확실함)
3. **`class`나 `def`로 시작하는 줄을 찾는다** → 이 파일 안에서 그 이름이 정의되어 있으면 🟠, 없으면 어딘가에서 `import`된 것
4. **모르는 이름이 나오면**: 그 파일의 `import` 문에서 어느 모듈 소속인지 먼저 확인하고, 공식 문서(예: PyTorch 문서)에서 검색

이 순서로 보면 아무리 큰 프로젝트라도 "내가 이해해야 할 부분(🟠)"과 "그냥 문서를 찾아보면 되는 부분(🟢🟣)"을 빠르게 나눌 수 있다.
